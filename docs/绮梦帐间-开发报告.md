# 绮梦帐间 — 一个 Vibe Coder 的完整产品开发报告

> 作者：小黒秋（19岁，软件技术专业学生）  
> 开发周期：2026年4月26日 — 5月25日（30天）  
> 协作方式：Vibe Coding + OpenClaw AI 助手  
> 最终产出：一个可安装的跨设备同步个人记账 PWA  

---

## 一、项目缘起：不是缺一个记账软件，是缺一面镜子

我每月生活费 1000 块，靠游戏陪玩赚零花钱。收入不稳定，消费欲却很强。市面上的记账软件都有一个隐含的预设：你是一个有稳定收入的成年人。它们用红绿色的柱状图告诉你"超支了"，但没有告诉我——**这笔钱花得值不值**。

所以我决定自己做。

核心理念只有一句话：**记账是记录存在，不是批判消费。财务软件应该是镜子，不是鞭子。**

我给这个项目起名「绮梦帐间」——绮丽的梦，账本之间。一个19岁学生的个人财务避难所。

## 二、开发方式：用 OpenClaw 做的 Vibe Coding

### 什么是 Vibe Coding？

Vibe Coding 不是"让 AI 写代码，你看着"。而是：**你描述你想要的感觉和体验，AI 负责实现细节，你负责判断**。

### OpenClaw 的角色

OpenClaw 是我的 AI 开发伙伴。它不是那种问一句答一句的聊天机器人——它有持续性的记忆、能同时运行多个编码代理、能用 Skill 系统调用专业设计能力。

我使用的关键 Skill：

| Skill | 用途 | 关键贡献 |
|-------|------|---------|
| **design-taste-frontend** | UI/UX 设计规范 | 定义了整个产品的视觉语言：暖米色新拟物风格（Neumorphism）、Bento 非对称网格。禁止了三列等宽卡片、禁止了 AI 紫/蓝色渐变——这些规则把一个"AI生成的界面"变成了"有灵魂的设计" |
| **Superpowers (SpecKit)** | 设计规约驱动开发 | 在写代码之前先写了三版设计文档（v1/v2/v3），把"想要什么"写清楚再动手，避免边写边改 |
| **github** | 版本管理 | 所有代码变更都有清晰的 commit message，96 次提交构成了完整的开发叙事 |

### 协作模式

我不是给 AI 下命令，而是和它对话：

- 「这个钱包余额卡片的设计太像报表了，能不能做成更像艺术品的？」
- 「移动端每张卡片占一整行太浪费了，帮我优化」
- 「为什么点击清除数据没用？帮我排查」

OpenClaw 不只是写代码——它会读文档、查错误日志、运行数据库迁移、部署到 Vercel。我们之间的分工是：**我做产品决策，它做工程执行。**

## 三、开发历程：30 天，96 次提交

### 第1周：原型探索（4/26 — 5/6）

写了三版 Superpowers 设计规约。第一版想做 3D 粒子效果，后来意识到太重了，砍掉改成纯 CSS。这个决定很关键——如果一开始就被 Three.js 拖住，后面所有功能都做不完。

### 第2周：核心闭环（5/7 — 5/9）

**最密集的 48 小时。** 完成了 Dashboard、魔法输入框、许愿星体、工作台、报表、多账户、预算系统。记账→查看→分析→储蓄的完整闭环跑通了。

魔法输入是整个产品的心脏：「比心 150 2小时 老板小李」——一句话完成记账。不用选分类、不用填表单。这个功能定义了产品的气质：**记账应该是自然的，不是填表的。**

### 第3周：打磨 + 扩展（5/10 — 5/16）

加了四个进阶功能：周期性记账、标签系统、债务追踪、历史记录增强。同一天做了 Taste Skill 视觉升级——字体、动画、交互全面优化。加了金鹅、自由进度、财务健康这些"不只是记账"的东西。

这周最重要的是**信息架构重构**：Dashboard 从"小 Reports"回归"今日操作台"，Reports 成为唯一的复盘中心，Workbench 专注赚钱效率。每个页面有明确的边界——一个信息只在一个地方出现。

### 第4周：上线 + 同步（5/20 — 5/25）

**最艰难但最有成就感的一周。** 做了六件事：

1. **移动端适配** — Dashboard/Wishes/Settings 全面适配，Workbench 用 Bento 非对称网格优化
2. **代码分割** — 首屏从 1.9MB 降到 327KB，减少了 6 倍
3. **PWA 安装** — 手机桌面图标、启动画面、离线使用
4. **新图标** — 金羽笔 + 星，暖金色调
5. **Supabase 云同步** — 手机和电脑数据实时互通
6. **Vercel 部署** — 国内直连的线上版本

第五步踩了最大的坑：PostgreSQL 自动把小写驼峰转成小写，数据存在云端但读取时字段对不上。排查了两个小时才找到根因——所有建表语句的驼峰列名必须用双引号包裹。

## 五、踩过的坑（技术笔记）

### 坑1：PostgreSQL 列名大小写（卡了最久）

PostgreSQL 把未加引号的列名自动转小写。`CREATE TABLE (createdAt BIGINT)` → 实际列名 `createdat`。前端 `{ createdAt: 123 }` 发过去找不到字段。建表时所有驼峰列名必须用双引号：`"createdAt" BIGINT`。

### 坑2：PWA 不自动更新

`registerType: 'autoUpdate'` 在独立 App 模式下不会触发检查。必须自定义 Service Worker，监听 `visibilitychange`。而且旧版本没有新 SW 逻辑——第一次必须手动删了重装。

### 坑3：React.lazy() 只认 default export

页面用了 `export function Dashboard()`（命名导出），`lazy()` 只接受 default。用 `.then(m => ({ default: m.Dashboard }))` 桥接。

### 坑4：清除数据被云端复活

`initDefaultAccounts` 和 `fullSync` 并行执行导致竞态条件——清空表的同时初始化了默认钱包，然后云端拉回了旧数据。改成顺序执行修复。

### 坑5：Vercel 部署需要手动配环境变量

`VITE_*` 变量是构建时注入的，只在 Vercel Dashboard 里配置不会自动生效——必须触发一次 Redeploy。

## 六、Vibe Coding 的感悟

### AI 不会替你做产品决策

OpenClaw 可以帮我写 1000 行代码、排查一个 PostgreSQL 的隐藏 bug、设计一套完整的颜色系统。但它不知道"这个功能值不值得做"。那个判断永远是我的——因为只有我知道自己的月生活费是 1000 块，只有我知道什么界面让我感觉温暖而不是焦虑。

### Skill 系统是区分"AI 写代码"和"AI 做设计"的临界点

Taste Skill 不是让 AI 变得更聪明——是给它一套**规则**：禁止 AI 紫、禁止三列等宽卡片、强制 Bento 非对称网格。这些规则把一个"能看的界面"变成了"有灵魂的设计"。没有 Skill 的 AI 写出来的 UI 一看就是 AI 写的。

### 迭代比规划重要

第一版设计想做 3D 粒子效果，第二版想做 WebGL 星体可视化。最后全砍了——不是因为做不出来，是因为做出来也没人用。快速做出来 → 用起来 → 发现不需要 → 砍掉。这个循环比"一开始就想清楚"高效得多。

### 从 "I can't build this" 到 "I built this"

一个月前，我只会基础的 HTML/CSS/JS。一个月后，我做了一个完整的 PWA：React + TypeScript + PostgreSQL + 自动部署 + 云同步。

不是因为我变聪明了。是因为 AI 把执行层打通了，我只需要负责判断和选择。
