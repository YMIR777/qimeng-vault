## 一、多账户管理实现方案

### 当前问题

现在系统是**"流水账模式"**：
- 记录收入/支出 → 计算总资产（收入 - 支出）
- 总资产是**虚拟数字**，不绑定任何实际账户
- 用户不知道"微信里有多少钱""银行卡里有多少钱"

### 两种实现路径

#### 方案 A：轻量多账户（推荐）

**新增数据结构：**
```typescript
interface Account {
  id: string;
  name: string;        // "微信钱包"
  type: 'wechat' | 'alipay' | 'bank' | 'cash';
  balance: number;     // 当前余额（用户手动维护 or 自动计算）
  color: string;       // 标识色
  icon: string;        // SVG 图标
  createdAt: number;
}
```

**交易表增加字段：**
```typescript
interface Transaction {
  // ... 现有字段
  accountId?: string;  // 关联账户
  toAccountId?: string;  // 转账目标账户（如果是转账类型）
}
```

**UI 改动：**
1. **Dashboard 资产卡片** → 改为"账户总览"，显示各账户余额 + 总资产
2. **记账时选择账户** → 魔法输入框解析后，弹出账户选择（或记住上次选择）
3. **新增转账功能** → 从一个账户转到另一个账户（如微信提现到银行卡）
4. **新增账户管理页** → 在 TabBar 加"设置"入口，管理账户列表

**优点：**
- 改动量可控（1-2 天完成）
- 解决核心痛点（知道每个账户有多少钱）
- 为后续预算、对账打基础

**缺点：**
- 需要用户手动初始化账户余额
- 转账功能需要额外 UI

---

#### 方案 B：完整版（暂不推荐）

增加：
- 信用卡账单周期管理
- 账户对账（系统余额 vs 实际余额）
- 投资账户（股票、基金收益率）
- 多币种支持

**问题：** 对于个人/陪玩场景过度设计，用户不一定有投资、外币需求。

## 三、缺失功能详解

### 🔴 高优先级缺失

#### 1. 多账户管理（影响最大）

**用户场景：**
- "我想知道微信里还有多少钱"
- "支付宝和银行卡加起来总资产是多少"
- "我从微信提现 500 到银行卡，怎么记？"

**实现建议：** 方案 A（轻量版）

---

#### 2. 预算管理系统

**用户场景：**
- "这个月餐饮预算 800，已经花了 650，只剩 150 了"
- "超预算时提醒我"

**实现方案：**
```typescript
interface Budget {
  id: string;
  category: string;     // "餐饮"
  amount: number;       // 月度预算额
  period: 'monthly';    // 可扩展 weekly/yearly
  rollover: boolean;    // 未用完是否累积到下月
}
```

**UI：**
- Dashboard 或 Reports 增加"预算进度"区块
- 环形进度条：已用 / 预算
- 超预算时颜色变红 + 提示

**工作量：** 中等（半天到一天）

---

### 🟡 中优先级缺失

#### 3. 周期性记账（自动记账）

**用户场景：**
- "房租每月 1 号扣 1500"
- "iCloud 订阅每月扣 21"
- "工资每月 15 号发"

**实现方案：**
```typescript
interface Recurring {
  id: string;
  name: string;         // "房租"
  amount: number;
  type: 'income' | 'expense';
  category?: string;
  accountId?: string;
  frequency: 'daily' | 'weekly' | 'monthly';
  startDate: number;
  endDate?: number;     // 可选终止日期
  lastExecuted?: number;
}
```

**执行逻辑：**
- 每次打开应用时检查：上次执行到今天，有没有需要生成的周期性交易
- 自动生成交易记录，标记 `recurringId`

**工作量：** 较高（1-2 天）

---

#### 4. 标签系统

**与分类的区别：**
- 分类：单维度（餐饮/交通/娱乐）
- 标签：多维度（"出差"、"春节"、"帮朋友代付"）

**一个交易可以有多个标签**，方便跨分类统计。

**工作量：** 低（半天）

---

#### 5. 债务/借贷追踪

**用户场景：**
- "借给朋友 500，还没还"
- "欠室友 200 电费"

**实现：** 新增 "借贷" 交易类型，有借款人和还款状态。

**工作量：** 中等

---

### 🟢 低优先级（锦上添花）

#### 6. 云端备份 + 多设备同步

- 现在只有本地 IndexedDB + JSON 导出
- 可接 Firebase / Supabase 免费版
- 或者 GitHub Gist 备份（免费）

#### 7. 账单凭证拍照

- 手机端用摄像头拍收据
- 交易关联图片文件

#### 8. 投资账户

- 股票、基金持仓追踪
- 收益率计算
- 对于学生/陪玩场景优先级低

## 四、推荐路线图

### 路线 A：实用主义（推荐）

按用户痛点排序：
1. **多账户管理**（方案 A 轻量版）— 解决"不知道各账户余额"的问题
2. **预算系统** — 解决"花钱没节制"的问题
3. **周期性记账** — 解决"重复记账麻烦"的问题

### 路线 B：完善主义

把现有页面打磨到极致：
- 移动端适配优化
- 更多图表类型（Sankey 资金流向、日历热力图）
- 更丰富的动画

### 路线 C：部署上线

- PWA 打包
- GitHub Pages / Vercel 部署
- 手机桌面图标

## 五、我的建议

**现在做「多账户管理」最合适**，原因：
1. 设计文档里已经有规划（Task 6）
2. 你的核心痛点是"陪玩收入分散在多个平台"
3. 实现量可控，1-2 天能做完
4. 为预算、报表增强打基础

**多账户做完后 → 预算系统 → 周期性记账 → 部署上线**

这个顺序是从"解决最痛的问题"到"自动化减负"到"对外发布"。
