## 5. 魔法输入框

### 5.1 输入识别逻辑

**关键词 → 属性映射：**

| 属性 | 关键词（不区分顺序） |
|------|-------------------|
| 平台 | 含 `比心`→比心，`微信`→微信，`抖音`→抖音，`小红书`→小红书，`建行`→建行，`招行`→招行 |
| 金额 | 提取所有数字，取**最大值** |
| 收入/支出 | 含 `转`/`收到`/`收入`/`到账` → 收入；含 `花了`/`支出`/`买`/`消费`/`转出` → 支出 |
| 老板名 | `老板`/`甲`/`乙`/`丙`/`丁` 紧跟的文字 |
| 时间/时长 | 含 `h`/`小时`/`分钟` 时提取数字（分钟） |

**识别结果判断：**
- 收入：平台 + 金额 → ✅ 可直接记账（老板名可缺省）
- 收入：金额Only → ⚠️ 需补充平台
- 支出：金额 + 分类 → ✅ 可直接记账
- 支出：金额Only → ⚠️ 需补充分类
- 无法判定类型 → ⚠️ 提示用户

### 5.2 信息不足时的补充表单

弹出 Modal，包含：
- **收入：** 平台（下拉选择）、金额（预填）、老板名（可选填）、备注（可选）
- **支出：** 分类（下拉选择）、金额（预填）、备注（可选）

用户点击确认后才正式写入。

### 5.3 输入成功反馈

记账成功后：
- 输入框下方显示一行轻量 toast："+150 元（比心收入）"，2秒后消失
- 总资产数字滚动更新（保留现有动画）

## 6. 支出决策流程

### 6.1 触发条件

用户输入被识别为**支出**后，进入决策流程。

### 6.2 UI 流程

```
输入 "打车30" → 回车
    ↓
支出决策卡片从底部滑入
    ↓
┌─────────────────────────────┐
│  "打车 30元"               │
│                             │
│  ○ 值得    ● 不值          │  ← 两个按钮，选中态有颜色变化
│                             │
│  [取消]       [确认]        │  ← 确认后写入
└─────────────────────────────┘
```

- **值得：** 按钮边框变绿金光晕，卡片整体微亮
- **不值：** 按钮边框变暗红，卡片微抖（CSS keyframe）
- **取消：** 卡片滑出，无任何操作

### 6.3 记账写入

写入数据：
```typescript
{
  type: 'expense',
  amount: 30,
  category: '交通',       // 自动识别或用户选择
  judgment: 'worthy',     // 或 'unworthy'
  note: '打车',
  date: Date.now()
}
```

## 8. 技术方案

### 8.1 依赖调整

| 操作 | 依赖 |
|------|------|
| 移除 | three, @react-three/fiber, @react-three/drei, gsap |
| 添加 | react-router-dom, dexie（IndexedDB） |
| 保留 | react, react-dom, vite, typescript |

### 8.2 目录结构（本次相关）

```
src/
  components/
    ui/          # TabBar、Card、Modal、Toast
    magic/        # MagicInput、ExpenseDecision、SupplementForm
  pages/
    Dashboard.tsx
    Wishes.tsx
    Workbench.tsx
    Reports.tsx
  store/
    db.ts         # Dexie 数据库定义
    useLedger.ts  # 记账 hook
  styles/
    global.css    # 更新为 v3 色彩系统
  App.tsx         # 清理后：路由 + TabBar 布局
```

### 8.3 数据写入流程

```
MagicInput 回车
    ↓
parseInput() 解析输入
    ↓
判断：收入？支出？信息完整？
    ├── 收入 + 信息完整 → 直接写入 → toast 成功
    ├── 收入 + 信息不足 → 弹出 SupplementForm（收入模式）→ 用户确认 → 写入
    └── 支出 → 弹出 ExpenseDecision
              ├── 用户点"值得" → SupplementForm（支出模式，可选分类）→ 写入
              ├── 用户点"不值" → 直接写入 judgment='unworthy'
              └── 用户点"取消" → 无操作
```
